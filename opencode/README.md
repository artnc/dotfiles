# OpenCode

`install.sh` symlinks the shared `opencode.json` and a hostname-selected work or personal profile as `opencode.jsonc`.

CLI preferences need different handling because OpenCode replaces `cli.json` atomically, which breaks a file symlink. The installer merges this repo's `cli.json` into the live file. The local `settings-sync` TUI plugin syncs fields changed in the UI back into this repo, preserving unrelated repo edits without copying runtime or credential files.

Run `./install.sh` after editing the tracked CLI settings. Restart the TUI after adding the sync plugin so that it starts watching saves. Run `make -C opencode test` from the repo root to test the plugins.

Run `make -C opencode test-native` for native footer compatibility tests. Setup downloads checksum-verified OpenCode V2.2.2 source and exact renderer dependencies into `/tmp`. Passing runs delete their workspace but keep the shared npm cache. The tests render the real native footer, goal, `/btw`, metadata, and slot components, plus the footer JSX and interrupt component extracted unchanged from the native prompt. Backend calls, theme providers, dialog hosting, and decorative animation use test adapters. No real prompts, goals, or worktrees are created. The tests cover goal states/clicks, `/btw` completion, worktree progress, shell and interrupt hints, activity counts, narrow terminals, unknown status contributions, and metadata warnings.

The `hide-activity-summary` TUI plugin always hides tool-count summaries and agent/model/timing footers and removes the session viewport's decorative side gutters and bottom padding, without adding commands or preferences. Native scrollbar/sidebar space and inner message/input padding stay intact. Native footer/status subtrees are excluded from transcript filtering, including unfamiliar status controls. Structural cleanup is enabled only on the tested OpenCode V2.2.2 layout and leaves other versions untouched. It leaves permission controls, error and retry notices, interrupted turn footers, expanded tool details, and running status labels visible.

The `prompt-footer` plugin only adds model, reasoning-variant, and connected-MCP controls through `prompt.footer`. Click the model or effort to open its native selector, or the MCP count to toggle the right sidebar. The count follows the current workspace and excludes disabled, failed, pending, and unauthenticated servers. The bundled footer stays enabled, and `prompt.footer.status` is never replaced. Native OpenCode owns the location menu, `/goal`, `/btw`, worktree progress, subagent/shell activity, shell-mode exit hint, and context/cost formatting. Only standalone `agents`/`commands` hint leaves with matching live bindings and the tested native label structure are hidden. Operational hints and unrecognized UI remain visible. Supplemental controls yield to native UI in shell mode and below 100 columns. The native full path and token count are intentionally retained until finer-grained customization hooks exist. The metadata-hiding plugin still removes the duplicate model row below the prompt input, unless it shows auto-accept mode or a usage limit.

The `half-cell-padding` plugin paints a `▄` top edge on the input and matching `▄`/`▀` edges on previous user turns. Native padding, text, hit targets, and scroll anchors stay unchanged. Like structural cleanup, it only runs on the tested OpenCode V2.2.2 layout. Disabling the plugin restores the original paint hooks.
